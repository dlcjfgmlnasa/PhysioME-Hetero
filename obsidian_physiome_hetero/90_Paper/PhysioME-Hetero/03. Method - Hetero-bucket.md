# 03. Method - Hetero-bucket sampling

## 3.1 설계 동기

문제: 한 batch 안에 ABP-only / ECG+PPG / ABP+ECG+PPG 등 가용성이 다른 sample을 섞으면, 멀티모달 인코더의 입력 형태가 sample마다 달라져 효율적 batch 처리가 어렵다.

해결: **batch 내부는 동질, batch 간은 이질**. 모달리티 가용성 패턴별로 bucket을 만들고, 한 batch는 한 bucket에서만 추출.

## 3.2 Bucket 정의

각 case `c`의 segment `s`에 대해 modality presence bitmap

$$
b_{c,s} = (m_{c,s,\text{ABP}}, m_{c,s,\text{ECG}}, m_{c,s,\text{PPG}}) \in \{0,1\}^3
$$

7개의 비-empty bitmap 가능 (`100`, `010`, `001`, `110`, `101`, `011`, `111`).

각 segment는 정확히 한 bucket에 속한다.

## 3.3 Sampling 전략

**Natural** (default): bucket별 segment 수에 비례하여 batch 추출
- 학습 분포 ≈ 배포 분포라는 가정에 가장 충실
- 큰 bucket이 학습 빈도 높음

**Uniform**: 모든 (eligible) bucket에 동일 시간 부여
- 작은 bucket 과적합 위험은 있으나, 결손 robust성 학습에 유리
- Ablation 후보

## 3.5 데이터 측면 — 새 SSL 파서

기존 `vital_db.py`는 `is_all_in(subject_modal_names, modal_names)` 필터로 ABP+ECG+PPG 모두 보유한 case만 유지. 우리 새 파서 `vital_db_ssl.py`:

- 가용한 모달만 부분 저장
- per-segment validity mask 동봉
- 신호별 robust 전처리 ([[06. Experiments 설계#전처리 파이프라인]])

→ VitalDB 데이터 활용도 100%로 회복.

## 3.6 Backbone 인코더 — uni2ts 계열 Transformer로 교체

원본 PhysioME의 인코더는 timm ViT ``Block`` (LayerNorm + MHA + GELU FFN) + sinusoidal `pos_embed` + ``interpolate_1d_pos_embed``로 가변 길이를 처리했다. 우리는 이를 [Biosignal-Foundation-Model의 ``module/transformer.py``](https://github.com/dlcjfgmlnasa/Biosignal-Foundation-Model)에서 가져온 **uni2ts (Salesforce, Apache 2.0) 기반 Transformer**로 교체했다 (``models/transformer/``).

핵심 차이:
- **RMSNorm** (LayerNorm 대비 빠르고 안정)
- **GQA** (Grouped Query Attention; default ``num_groups=num_heads``로 MHA로 동작, 향후 KV cache 공유 가능성)
- **GLU FFN** (SiLU-gated FFN; LLaMA 계열 표준)
- **RoPE** (위치 정보를 attention 안에서 회전으로 주입; ``QueryKeyProjection + RotaryProjection``)
- ``d_cond=0`` 모드로 AdaLN 비활성화 (PhysioME에는 condition vector 없음)

장점:
1. 단일 backbone 코드베이스를 두 프로젝트(PhysioME-Hetero / Biosignal-Foundation-Model)에서 공유 → maintenance cost 1/2
2. RoPE 덕에 Phase-1(60s) ↔ Phase-2(임의 길이) 전이 시 interpolation 단계 불필요
3. LoRA target은 GQA의 ``out_proj`` (원본 ``attn.proj``의 새 명칭)

## 3.7 원본 PhysioME에서 발견된 버그

> [!warning] 본 paper에서 명시 후 fix
> 원본 코드를 면밀 검토하여 두 가지 버그 발견. **A1 baseline은 우리 코드에서 재학습**하여 공정 비교.

### 버그 1 — `forward_restoration_decoder` split_size 불일치

`forward_restoration_decoder`의 caller가 encoder를 **kept modal만** 통과시킴 → encoder 출력 길이는 ``num_kept * frames``. 그러나 decoder는 ``len(ids_restores) == num_total``로 split → ``split_size = (num_kept * frames) // num_total``. 결과적으로 dropped modal에 해당하는 슬라이스가 kept modal 토큰 일부에서 잘려나옴 — restoration semantics가 의미를 잃음.

**Fix** — encoder 입력 단계에서 dropped modal slot에 학습 가능한 ``dropped_modality_token``을 padding 방식으로 채워 encoder 출력을 항상 ``num_total * frames``로 유지.

### 버그 2 — decoder 출력의 `.detach()` 위치

원본 `forward_decoder` / `forward_restoration_decoder` 모두 마지막에:

```python
reconstructed_patches.append(x.detach().contiguous())
```

→ decoder 가중치는 inter-recon / restoration loss로부터 grad를 받지 못함. **결과: 학습되지 않음**. (학습 신호는 cross-contrastive 손실만이 유효).

**Fix** — `.detach()` 제거, target tensor (``real_tokens``)를 명시적으로 detach (정확한 stop-gradient 의도).
