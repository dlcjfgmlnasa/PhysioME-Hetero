# 05. Method - 3-state presence embedding

## 5.1 동기

모델 입장에서 "ABP가 없다"는 두 가지 다른 의미일 수 있다:

| 상태 | 의미 | 학습 시 빈도 |
|---|---|---|
| **Real-present (0)** | 측정되었고 신뢰 가능한 신호 존재 | 매 가용 batch |
| **Synthetically-dropped (1)** | 측정은 되었지만 학습 시점에 우리가 가렸음. **GT 보유** | restoration phase에서만 |
| **Naturally-absent (2)** | 애초에 측정되지 않음. **GT 없음** | hetero batch에서 |

이 셋을 모델에 명시적으로 알려주지 않으면, 추론 시 모델은 "naturally-absent"인 ABP를 마치 "synth-dropped"처럼 처리하여 restoration decoder를 잘못 사용하거나, 반대로 가능한 복원을 시도하지 않는 등 일관성 잃은 행동을 할 수 있다.

## 5.2 구현

`models/physiome/model.py`:

```python
PRESENCE_REAL = 0
PRESENCE_SYNTH_DROPPED = 1
PRESENCE_NATURALLY_ABSENT = 2
NUM_PRESENCE_STATES = 3

self.presence_state_embed = nn.Embedding(NUM_PRESENCE_STATES, encoder_embed_dim)
```

각 모달리티 토큰에 modal_token + pos_embed에 더해 ``presence_state_embed(state)``가 broadcast 가산.

## 5.3 학습 / 추론 시 state 매핑

| 시나리오 | state assignment |
|---|---|
| Hetero batch (학습) | 가용 모달 = 0, 결손 모달 = 2 |
| Restoration phase (학습) | kept = 0, synth-dropped = 1, naturally-absent = 2 |
| Inference w/ all modals | 모두 = 0 |
| Inference w/ missing modals | 가용 = 0, 결손 = 2 |

## 5.4 학습 동역학 — 어느 state가 grad 받나?

[[../참고/저자 메모]]에도 기록된 디자인 결정:

- **state 0 (real)**: forward_encoder 통과 시 자주 등장 → grad 풍부
- **state 2 (absent)**: hetero batch의 결손 위치에서 등장 → grad 받음 (인코더가 결손 인식 학습)
- **state 1 (synth-dropped)**: ``_synthetic_drop_restoration``의 encoder는 ``no_grad`` (원본 PhysioME의 encoder gradient stop을 보존). 따라서 state 1 row는 직접 grad 안 받지만, 작은 영향이긴 하나 weight init 단계의 random 값에서 시작.

> [!note] 디자인 트레이드오프
> state 1 row가 grad를 안 받는 점은 encoder를 frozen으로 두는 원본 설계의 자연스러운 귀결. encoder gradient stop을 풀면 state 1도 학습되지만, 이는 PhysioME의 design intent에서 벗어남. v1은 보존, v2 ablation 후보.

## 5.5 Encoder 입력 합성 (수식)

각 모달리티 $m$, sample index $i$의 state $s_{i,m} \in \{0,1,2\}$:

$$
\tilde{z}_{m, i} = \mathrm{Patch}(x_{m,i}) + e_m + p + \boldsymbol{\sigma}(s_{i,m})
$$

여기서 $\boldsymbol{\sigma}: \{0,1,2\} \to \mathbb{R}^d$가 학습 가능한 presence embedding.

