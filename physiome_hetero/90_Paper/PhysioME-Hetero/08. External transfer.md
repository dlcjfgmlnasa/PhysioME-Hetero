# 08. External transfer — MIMIC-III Waveform Database

## 8.1 목적

> [!quote]
> Reviewer "단일 데이터셋(VitalDB)에서만 동작하는 거 아니냐"의 직접 카운터.

VitalDB에서 pretraining한 모델이 **MIMIC-III Waveform Matched Subset** (미국 ICU, 다른 인구·다른 측정 환경)에 zero-shot/linear probing으로 transfer 가능함을 보임.

## 8.2 데이터

### MIMIC-III Waveform Matched Subset
- ~10,282 환자, PhysioNet 공개 ([https://physionet.org/content/mimic3wdb-matched/1.0/](https://physionet.org/content/mimic3wdb-matched/1.0/))
- 채널: ABP/ART, PLETH (PPG), II/I/III/V (ECG)
- Native SR 125 Hz → resample 100 Hz
- ICU 환경 (VitalDB는 OR) — 환자/측정 분포 차이 큼

### Why this subset
- **Intersection of modalities**: ABP/ECG/PPG 모두 가용 (VitalDB와 매칭)
- **Open access** (별도 신청 없음)
- **임상 시나리오 차이 명확**: 미국 ICU vs 한국 OR — domain shift 강함

## 8.3 파이프라인

기존 작성된 파일 사용:
- `dataset/data_parser/mimic3_waveform_ssl.py` — wfdb 스트리밍 + 채널 매칭 + 우리 전처리 + hetero npz 출력
- 명령:
  ```bash
  # 1. ABP-bearing 레코드 manifest 스캔
  python -m dataset.data_parser.mimic3_waveform_ssl scan \
      --max_records 200 --manifest data/mimic3_ssl/manifest.json

  # 2. Parse N records → hetero npz
  python -m dataset.data_parser.mimic3_waveform_ssl parse \
      --manifest data/mimic3_ssl/manifest.json \
      --trg_path data/mimic3_ssl --n_cases 100
  ```

## 8.4 평가 시나리오

### Scenario 1: Zero-shot
- VitalDB로 pretraining한 PhysioME-Hetero를 그대로 사용
- MIMIC-III 데이터에서 IOH 평가 (MAP<65 사용 가능 — 동일 임상 정의)
- "분포 변화에도 표현이 유지되는가"

### Scenario 2: Linear probing
- Encoder frozen
- 분류 head만 MIMIC-III train split에서 학습
- "표현이 새 도메인에 적응 가능한가"

### Scenario 3 (선택): Mortality prediction
- ICU mortality는 MIMIC-III의 자연스러운 task
- VitalDB는 OR 환경이라 in-hospital mortality와 직접 매칭 어려움
- Cross-dataset generalization story로 가장 강함
