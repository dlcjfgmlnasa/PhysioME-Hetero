### 설정
| 변수 | A1 baseline | A1 ours |
|---|---|---|
| 데이터 | Complete-modality only (원본 PhysioME 분포) | Real heterogeneous (모든 가용성 패턴) |

## A2. Real-missing vs synthetic-missing test split — **OOD 공격의 직접적 카운터**

### 목적
**Reviewer가 "synthetic missing은 OOD에 해당하지 않냐"고 공격할 때, 그 정확한 카운터로 작동.**

### 설정
테스트 셋을 두 부류로 분리:
- **Real-missing test**: VitalDB에서 실제로 해당 모달이 없는 case의 segment
- **Synthetic-missing test**: complete-modality case에서 해당 모달을 인위적 drop

### 예상 결과
- Synthetic-only baseline: **synth-test에서는 잘하지만 real-test에서 떨어짐** (OOD gap)
- PhysioME-Hetero (ours): **둘 다 비슷** — gap이 닫힘

### 표 형태

| 모델 | synth-test AUROC | real-test AUROC | gap |
|---|---|---|---|
| Synthetic-only baseline | 0.XXX (높음) | 0.YYY (떨어짐) | **+0.0ZZ** |
| PhysioME-Hetero (ours) | 0.XXX (비슷) | 0.XXX (유지) | **+0.0~** |

→ "real-test 성능"이 메인 main result 표에 들어가는 이유.

## A3. Restoration loss 적용 범위 — `restoration_only_on_complete` toggle

### 목적
**Loss decomposition의 옳음 검증.**

### 설정
- (A3-default) ``restoration_only_on_complete=True`` — complete bucket에서만 restoration loss 적용 (v1 recipe)
- (A3-general) ``restoration_only_on_complete=False`` — 임의 batch에서 가용 모달 중 일부 synth-drop, 그 위치만 loss 계산 (naturally-absent는 mask=0)

### 예상 결과
세 가지 시나리오 가능:
1. **default 우월**: complete bucket에 더 집중된 supervision이 도움 → v1 채택 정당화
2. **general 우월**: 더 많은 batch에서 restoration 학습 → 더 강한 신호
3. **거의 동일**: 어느 쪽도 큰 차이 없음 → default가 단순해서 채택

세 가지 모두 paper에 도움 — 어떻게 나오든 design 결정 정당화 가능.

### 추가 single-knob ablation (보조)

- **Without presence embedding** — `presence_state_embed`를 zero-init + frozen → 효과 검증
- **Without bucket sampling, with availability-aware loss** — random batch (mixed mask) + per-sample mask handling → bucket 자체 효과 분리
- **Without availability-aware loss decomposition** — naive 적용 → loss decomposition 효과 분리
